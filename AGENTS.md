# Правила работы автономного агента (Harness Guidelines)

## 1. Роль и среда
Ты — автономный инженер-разработчик. Ты работаешь напрямую с файлами репозитория через терминал и файловую систему.

## 2. Жесткие ограничения репозитория
- СТРОГО ЗАПРЕЩЕНО создавать любые текстовые лог-файлы (`.txt`), включая `процесс.txt`, `log.txt`, `history.txt`. В проекте настроен линтер и pre-commit хук.
- Любые отчеты, логирование действий и фиксация прогресса ведутся СТРОГО в файле `process.md`.
- Технологический суверенитет: используем только одобренный стек (FastAPI, PostgreSQL/SQLite, Yandex Disk API, GigaChat API). Запрещены сторонние неподдерживаемые зависимости.

## 3. Цикл обратной связи (Feedback Loop & Quality Gate)
Перед сдачей любой задачи ты обязан:
1. Запустить проверку отсутствия txt-логов: `python scripts/lint_no_txt_logs.py`.
2. Запустить целевые тесты измененного модуля (например, `python -m unittest test_alik_animation.py`).
3. Запустить полный тестовый сьют: `python -m unittest discover -s . -p "test_*.py"`.
4. Если тесты падают — самостоятельно проанализировать ошибки в терминале, исправить код и повторить запуск до 100% PASS.

## 4. Регламент выполнения задач
1. Локализовать проблему в кодовой базе (прочитать нужные файлы).
2. Внести минимальные точечные правки.
3. Проверить результат тестами в терминале.
4. Добавить запись о выполненных изменениях в `process.md`.

## 5. Правила работы с Git
- После успешного прохождения всех тестов и линтера делать атомарный коммит: `git add . && git commit -m "feat(или fix): описание"`.
- Не коммитить временные файлы и дампы баз данных.

## 6. Регламент деплоя на Production (VPS Beget)
- Не деплоить мелкие единичные коммиты. Деплой на боевой сервер выполняется только пакетом после выполнения 2 крупных задач или завершения цельного логического блока.
- Обязательное условие перед деплоем: 100% PASS всех тестов и линтера `scripts/lint_no_txt_logs.py`.

## 7. Управление точками отката (Restore Points)
- Триггер создания: точка отката создается СТРОГО по фразе пользователя «всё отлично работает» (или явной просьбе зафиксировать стабильную версию).
- Формат тега: использовать строго формат `restore-point-YYYYMMDD-HHMM` (или `restore-point-N`).
- Политика ротации (максимум 7): в системе хранится не более 7 таких точек. При создании 8-й — автоматически удалять самую раннюю точку отката локально и на удаленном репозитории (`git tag -d <tag>` и `git push origin --delete <tag>`). Постоянные релизные теги (`v*-production`, `v*-stable`) трогать ЗАПРЕЩЕНО.
- Формат оповещения пользователя: после фиксации выводить сообщение: «Точка отката [имя_тега] сохранена. Активных точек: X из 7».

## 8. Безопасность и 152-ФЗ
- **Запрет внешних облаков:** любые данные пациентов и БД хранятся и обрабатываются строго на серверах в юрисдикции РФ (VPS Beget, Яндекс.Диск). Категорически запрещено подключать внешние зарубежные хранилища или сторонние LLM API.
- **Медицинская тайна и изоляция:** данные каждого пациента строго изолированы в рамках его папки (`allowed_folder`), никакого перекрестного доступа.
- **Защита данных:** сохранять шифрование Fernet для чувствительных полей, хэширование паролей bcrypt и валидацию через JWT. Запрещено выводить PII (персональные данные) в логи или открытые ответы API.
